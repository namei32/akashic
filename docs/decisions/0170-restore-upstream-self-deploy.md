# 0170 · 使用上游自部署入口与 worker

- 状态：accepted
- 日期：2026-11-27
- 关联：[0091](0091-shell-self-deployment.md)、[0169](0169-publisher-authority-is-independent.md)、RUN-013、CAP-001

维护者要求还原上游 Docker 自部署。采用上游的部署 Skill 和用户 systemd worker。会话使用 GitHub CLI 核验
PR 并按上游策略 squash，读取完整 main SHA 后只调用一次 `akashic-release submit`。宿主 worker 拉取并构建
目标，在同一任务中移交目标发布器，沿 0091 核对最终送达、排空、关闭、启动与回退。fork 仍以维护者
仓库为发布来源，实例路径由实际运行配置解析。

这个入口沿用上游的信任前提。启用前，部署者需要明确为运行身份配置 GitHub、Docker、mise 和系统服务权限。
同一账号或受其控制的值可以影响拥有 Docker 权限的程序时，不能把该账号视为受 0169 隔离的聊天账号。
0169 记录的旧部署及其回执保留，可在同一宿主上通过管理员恢复旧单元和入口。
旧资料不授权删减业务数据、改变 Windows 互操作或迁移其他服务。

先在独立内核虚拟机验收真实用户 worker 构建、最终回复送达和切换，并核对原消息及无关服务。由管理员
单独切换现有正式实例的权限与单元，核对原配置、插件和工作数据仍可使用。采用这条路径的代价是信任
运行身份与目标代码；如果需要在含其他敏感资产的主机上恢复隔离，应重新采用 0169 的独立发布权。
