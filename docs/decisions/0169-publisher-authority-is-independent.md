# 0169 · 宿主发布权独立于聊天与候选代码

- 状态：accepted
- 日期：2026-11-26
- 关联：CAP-001、CAP-002、RUN-013、STA-003、[0091](0091-shell-self-deployment.md)
- supersedes：0091 中以目标解释器执行目标发布器的高权限交接方式；回合、送达、排空和恢复合同保留。

## 背景与决定

免密入口、命令摘要和 worker cgroup 不能隔离一个仍会执行聊天账号可写代码的发布进程。
Docker 权限也不能因进程已降为普通 uid 而当成普通权限。维护者要求保留自部署，同时隔离发布权。

聊天进程通过受保护的 Unix socket 申请部署，只发送完整版本、原调用停止凭据和通知会话。
systemd 按连接启动短生命周期入口，按 SO_PEERCRED 校验账号；发布任务由独立系统单元执行。
不增加常驻发布 daemon，不向聊天账号授予 sudo 或 Docker socket。用户服务名、PID 和自填 uid 不作为授权。

管理员安装的发布器及其解释器、依赖、策略、制品批准记录、Compose 和系统单元，连同所有父目录，
均不可由聊天账号修改。应用更新不更新这些控制文件。发布器只激活管理员已批准的固定制品，
不执行目标仓库的发布脚本，不在生产 Docker daemon 上构建候选代码，不接收任意路径或 Docker 参数。
制品准备在无生产数据和发布权限的构建环境完成；批准固定提交、镜像摘要和制品清单摘要。
CI 和签名提供检查及来源证据，不能让候选代码自行修改批准政策。

```
聊天 / Shell ──版本与调用凭据──▶ 系统 socket 入口
                                      │ 校验固定策略与批准记录
                                      ▼
隔离构建 ──待批准制品──▶ 管理员 ──▶ 受保护发布器
                                      │ 排空、固定布局、检查与回退
                                      ▼
                         普通权限的 Core / Bridge
```

Workload Controller 属于受信任宿主控制面，其版本及政策独立于应用镜像固定。
工作负载的镜像、资源和宿主挂载受宿主政策约束，聊天输入不能扩大这些权限。
Host Bridge 的宿主 Shell 需隔离系统管理 socket、其他进程的 /proc 视图及 Windows 互操作入口；
不能只从 PATH 删除 Windows 可执行文件。管理员保留独立的维护入口。

## 数据、失败与代价

运行数据仍由原插件 owner 写入；此决定不授权删除、清空、减少或迁移业务数据。
发布请求和回执由宿主追加并推进状态，应用只能读取必要结果。旧回执保留，不自动重放失败任务。
无批准、凭据不符、制品漂移、待迁移或无法确认正常关闭时，拒绝发布并保存原因。
普通更新保留外置插件版本；数据迁移、控制面升级和权限扩大由管理员另行批准。

代价是首次安装控制面，以及为新制品建立独立批准记录。未选择给 worker 临时 Docker 组，
因为临时授予的权限仍可被候选代码使用；也未把 rootless Docker 当作同账号数据隔离。
若未来提供独立受保护的 CI 发布身份，可自动产生批准记录，但不得把该身份交给聊天进程。

验收包括真实更新和失败回退，以及修改候选脚本、环境、Compose、请求、服务名、挂载与 Windows
互操作尝试均不能扩大宿主权限；同时核对原消息、插件选择、配置和无关服务保留。
