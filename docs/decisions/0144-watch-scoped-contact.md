# 0144 · Watch 接管主动联系，后台权限保持原范围

依据：维护者明确选择直接替换，但不扩大后台权限。参照上游
`kachofugetsu09/akashic-agent@0345561845da6e912fbf25554ca1332692733b2a`
的 Watch 判读提示、三种去向和定时嘱托语法。没有移植脚本来源、文件检索工具、
通用后台会话、自由选择收件人或历史清理策略。

Watch 是唯一主动循环。保留 Wake、Drift 的插件 ID 是为了保留原配置、已归档的工具
绑定、在途请求、授权版本与记忆回执，不是并跑三套触发器。不修改既有数据库，也不
把历史私聊或记忆导入值班日志。EventMail 保留各类信封的原始身份及独立结算。
LOL 的新日报仍走专用会话；迁移前的告警由 EventMail 原版本领取，不重新生产日报。

## 运行与运维

- base 含 Watch；minimal 禁用。既有安装应核对实际插件选择包含新的 Watch 和相配套版本的
  Wake、Drift、EventMail，不要混用带旧触发器的归档。原主动联系未配置或关闭时不启动业务。
- 联系目标沿用原设置，不自动选人。不能由渠道证明为私聊时不调用分类模型、不投递。
  判读模型只见当前批次的短摘要与显式嘱托，唯一动作是返回 `decide`。不提供 Shell、
  改文件、任意读取记忆、联网抓取或 `message_push`。
- `wake` 立即交原权限流程判断，不等于送达；`inbox` 保存在待看，到期后才交回原流程；
  `log` 只记录。进入待看并不锁定来源，更不代表原发送成功，移交前重新核对版本。
  换目标不会把原待看事件重新分配给新收件人。Watch 的面板只列当前私人目标的检查及事件去向；
  原主动联系设置继续管理目标、暂停及记忆授权。
- Watch 插件配置：`model` 为可选分类模型 ID，默认跟随默认模型；`interval_seconds`
  默认 60，`digest_hours` 默认 4（0 关闭待看到期移交）。`orders` 为受信任的配置文本，
  分为 `## 叫醒我` 和 `## 留意`。例如 `- [工作日 10:00] 到点查看日程`。
  定时机会仍需显式启用原定时主动联系，只在原时间窗和频率下产生；错过的停机时间不补跑。
- 停止新联系用停用 Watch；原数据不删除。回退须整体恢复之前的插件组合并检查未结算的
  Watch 请求；不能让不认识新请求字段的旧代码消费它们。回退代码不撤回已送达消息。

验证入口：`scripts/drift_memory_wake_scenario.py --provider akasha` 或
`--provider default_memory`，只在一次性宿主和本地收件端运行，不试发到正式渠道。
